## Previously identified blockers — resolved

### Replayed application requests must re-authorize membership

`src/db/repositories/postgres-template-repository.ts` now locks and validates the active editor membership before reading an existing idempotency record. The unique-conflict recovery transaction repeats that authorization rather than returning the earlier project's details directly. A demotion, suspension, removal or membership deletion that commits first denies replay without returning the project.

Independent PostgreSQL execution passed the regression cases for all four revocations, unchanged members, deleted templates, conflicting requests, deleted projects, and a concurrent membership change.

### Template relationships must enforce the workspace boundary in SQL

`src/db/schema.pg.ts` and `drizzle-pg/0016_reusable_templates.sql` use composite workspace-aware foreign keys for template children and nested references. Application records have nullable link-workspace columns with explicit consistency checks, permitting `SET NULL` on deletion without clearing their required owning workspace. The project's referenced composite unique constraint is created before its dependent foreign key.

Independent tests rejected forged workspace relationships and missing link-workspace columns, accepted valid relationships, verified deletion behavior, and upgraded a populated pre-template database without changing existing project, milestone or task rows.

### Desktop tests must never use the installed profile

`desktop/main.js` relocates `userData` before profile access for an unpackaged test launch; a missing or relative test override refuses startup. Packaged builds and ordinary development launches ignore the override. The actual server paths are exposed only to unpackaged test code.

`tests/e2e/desktop.test.ts` asserts the actual profile, database, uploads, encryption-key and window-state paths before driving the app. It fingerprints the installed profile before launch and after quitting and removes only its own temporary directory. The template scenario now uses a fixed request key in that fresh profile.

Independent isolation and server-recovery unit checks passed 15/15. The combined shell suite subsequently passed twice, 11/11 each time, in different disposable profiles with the installed profile fingerprints unchanged.

## Limitations and follow-up

- These are automated and code-review results, not proof against every operational or security failure.
- Concurrency tests exercise specified races; they do not establish maximum production throughput.
- Desktop installer signing, distribution and every supported operating system were not independently exercised locally. Existing CI provides Linux desktop and Windows unit coverage.
- The Windows production build emitted `ENOENT` tracing-copy warnings for unrelated WindowsApps paths under the unchanged AI chat routes. The build exited 0 and both bundled shell runs passed. Investigate that tracing behavior separately before describing installer/distribution verification as warning-free; these runs do not establish coverage of every AI provider or a packaged installer.
- Do not run the installed Command Center app concurrently with the desktop suite: legitimate profile writes can fail its before/after fingerprint check.
- This change prevents future test writes to the installed profile. It does not remove any template rows created by earlier, non-isolated tests; deleting user data requires a separate explicit decision.
- The separate isolation worktree retains its original uncommitted changes until safe cleanup is explicitly accounted for. The task-date worktree is unrelated and untouched.
